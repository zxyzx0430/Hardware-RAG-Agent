# 交接单 250621-全面Review

## 任务
- **目标线程**：01-app ~ 08-infra
- **任务**：全面 Review 所有线程的实现质量、安全性、契约对齐
- **优先级**：高

## 起点

开工前先读：
1. AGENTS.md
2. docs/completed.md
3. docs/api-contract.md
4. docs/pitfalls.md

## Review 范围

### 1. 功能完整性 — 对照 api-contract.md

对每个接口（5.1 ~ 5.23），检查：
- [ ] 后端路由是否存在，路径和方法是否与文档一致
- [ ] 请求体验证（Pydantic schema 是否对齐文档字段）
- [ ] 响应体是否对齐标准格式（success / data / error）
- [ ] 错误码是否对齐 2.14 节错误码表
- [ ] 认证 Header 是否需要传递（2.5 节）
- [ ] SSE / WebSocket 事件结构是否与文档一致

### 2. 代码安全

注意：该项目是本地自部署（self-hosted），只监听 127.0.0.1，不暴露公网。
安全 Review 只关注本地风险，不需要管网络攻击类问题。

逐文件检查以下问题：

- [ ] API Key / Token 是否明文传输或明文存储
- [ ] dangerouslySetInnerHTML 是否经过 DOMPurify 消毒
- [ ] 异常信息是否脱敏（不把 API Key、路径等敏感信息返回前端）
- [ ] SQL/NoSQL 注入风险（参数化查询或 ORM 安全用法）
- [ ] 文件上传是否有类型/大小校验
- [ ] XSS 风险（用户输入是否在渲染前转义）
- [ ] CORS 配置是否过松
- [ ] 是否使用了不安全的 val() 或动态 import

### 3. 代码质量

- [ ] catch 块是否有静默吞错误（catch {} 无日志）
- [ ] 异步流式是否有超时控制
- [ ] 数据库会话是否使用上下文管理器（不用手动 try/finally）
- [ ] 消息/ID 是否用 UUID 而非 Date.now()
- [ ] 重试逻辑是否区分可恢复/不可恢复异常
- [ ] 前端 API 调用是否统一走封装函数（非裸 fetch）
- [ ] 状态管理中的异步操作是否有竞态处理
- [ ] 是否有硬编码的敏感信息/URL/端口

### 4. 文档对齐

- [ ] api-contract.md 中标记为 implemented 的接口，后端是否真实存在
- [ ] api-contract.md 中标记为 agreed 但未 implemented 的接口，是否有明确计划
- [ ] pitfalls.md 中已修复的问题是否在代码中真实修复了
- [ ] completed.md 的记录是否准确

### 5. 死代码与遗留问题

- [ ] 是否还有引用已删除/重命名的函数或模块
- [ ] 是否有注释掉的代码块
- [ ] 是否还有 mock 数据残留（本应切真实后端）
- [ ] 是否有 TODO/FIXME 需要评估
- [ ] 临时路由（如 main.py 里的 /api/xxx 直接返回逻辑）是否已迁移到正式模块

### 6. 可扩展性

- [ ] 新加一个 API 路由需要改几个文件？是否必须改 main.py？
- [ ] 新加一个 LLM Provider 是否只需改配置或少量代码？
- [ ] 前端新加一个页面/面板是否需要改 AppRoot / IconNav？
- [ ] 向量数据库切换（ChromaDB → 其他）是否耦合过紧？
- [ ] 工具函数是否有抽象层，还是直接内联在路由里？
- [ ] 数据库模型变更是否需要手动改多处代码？
- [ ] 是否有硬编码的限制（如上传文件大小、并发数、超时时间）应该抽成配置？

### 7. 虚假实现检查

逐接口检查是否存在以下情况：

- [ ] 路由存在但返回硬编码/空数据（如 /api/devices 返回空列表，但前端看起来像有数据）
- [ ] 接口返回 200 但 body 是占位 mock 数据
- [ ] 前端有功能按钮/菜单项但后端对应接口未实现
- [ ] 前端 mock 数据层是否已切真实后端（是否还有 mock 在 prod 路径下）
- [ ] 异常处理直接 pass 或返回空，没有实际逻辑
- [ ] 功能调用了不存在的模块/函数（如 sandbox_routes 引用 src.sandox.execute_code 但不存在）
- [ ] 数据库表已创建但对应的 CRUD 路由未实现
- [ ] WebSocket 端点已注册但连接后无实际数据流

### 8. 边界与降级

- [ ] 后端不可用时前端是否有合理降级（不是白屏或无限 loading）
- [ ] API Key 无效时是否有明确提示（不是通用 500）
- [ ] SSE 断连后是否有重试机制
- [ ] 流式中断时是否有部分结果保存
- [ ] 并发请求是否有队列或取消机制
- [ ] 知识库索引失败时是否有错误通知

按线程分段，每条问题格式：

`markdown
### 01-app

| 类别 | 严重度 | 文件 | 问题 | 建议 |
|------|--------|------|------|------|

- **P3**：建议优化，非必须
