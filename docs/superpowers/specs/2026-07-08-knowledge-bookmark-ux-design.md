# 知识库 / 收藏夹界面优化设计稿

> 日期：2026-07-08  
> 范围：前端组件 `KnowledgePanel`、`KbCollectionManager`、`BookmarkPanel` 及相关 CSS/i18n  
> 优先级：高（demo 前视觉收尾）

---

## 1. 背景与目标

用户在实际使用中发现两个明显影响体验的界面问题：

1. **知识库面板**：顶部「管理知识库」「+ 添加」两个按钮与中间的下拉选择器挤在一起，视觉上重叠/拥挤；同时列表下方存在「上传文档」拖拽区和底部「上传文件」按钮两个上传入口，功能重复、令人困惑。
2. **收藏夹面板**：文件夹是平铺展示，没有展开/收起能力。收藏内容多时，屏幕被大量展开的内容占满，难以快速定位文件夹。

本设计稿目标：在不改变底层上传/索引/收藏逻辑的前提下，对这两个面板做交互与视觉整理，使其更接近常见文件管理器的使用习惯。

---

## 2. 现状问题定位

### 2.1 知识库面板（`KnowledgePanel.tsx`）

- 顶部操作区把「标题/统计」「管理知识库按钮」「+ 添加按钮」「目标知识库下拉」「聊天检索范围按钮」「分块方式」「显示测试知识库复选框」全部堆在同一行，没有统一工具栏语义，导致按钮与下拉器之间距离过近，在小屏或缩放时看起来像重叠。
- 列表底部有 `DropZone` 虚线拖拽区；其下方又有一个独立的「上传文件」按钮（`fileInputRef` 触发）。两者触发同一 `handleFileSelect`，但视觉上形成两个上传入口。
- 当前 KB 信息卡片（`hardware-kb-card`）信息密度偏低，上下 padding 较大，挤占了文档列表空间。

### 2.2 收藏夹面板（`BookmarkPanel.tsx`）

- 每个文件夹渲染为一个卡片，内部收藏项始终可见，没有折叠能力。
- 文件夹头部仅显示名称和数量，缺少展开/收起 affordance。
- 空文件夹使用 inline style 的弱提示，未复用新的 `EmptyState` 组件。

### 2.3 管理知识库弹窗（`KbCollectionManager.tsx`）

- 新建知识库按钮样式与面板按钮不统一。
- 知识库列表/文档列表空状态仍是纯文字，可一并替换为 `EmptyState`。

---

## 3. 方案选择

| 方案 | 描述 | 适用场景 |
|------|------|----------|
| A 保守整理 | 只修复按钮重叠 + 合并上传入口 + 收藏夹加展开箭头 | 时间极紧 |
| **B 中等重构（推荐）** | 顶部工具栏语义化、合并上传入口、收藏夹树形化、管理弹窗联动优化 | **本次采用** |
| C 较大改版 | 知识库左侧面板+右侧文档列表、收藏夹侧边栏树、上传流程重做 | 适合后续大版本 |

本次采用 **方案 B**，改动量可控，体验提升明显，且能与已落地的 EmptyState / 按钮变体等组件保持一致。

---

## 4. 知识库面板改动

### 4.1 顶部工具栏重新排布

将顶部区域拆成三栏工具栏：

- **左侧（信息区）**：
  - 标题「知识库」
  - 启用数/总文档数/总片段数（保持现有数据，但字体缩小、间距收紧）
- **中间（筛选区）**：
  - 目标知识库下拉选择器
  - 聊天检索范围按钮
  - 分块方式只读文本（不再占用大段空间）
  - 「显示测试知识库」复选框（仅在调试模式下显示，或缩小为 icon + tooltip）
- **右侧（操作区）**：
  - 「管理知识库」按钮（`.btn-secondary`，齿轮图标）
  - 「上传文档」按钮（`.btn-primary`，加号图标）

工具栏使用 `flex-wrap` + `gap`，保证窗口缩小时自动换行，不会出现重叠。

### 4.2 合并重复上传入口

- 保留列表底部的大虚线拖拽区（`DropZone`）。
- **删除** 拖拽区下方的独立「上传文件」按钮。
- 拖拽区提示文案改为：
  - 中文：「拖拽文件到此处上传，或点击选择文件」
  - 英文："Drag files here or click to upload"
- 点击拖拽区仍然触发同一个隐藏 `input[type=file]`，功能不变。
- 已有文件超过 3 个时，拖拽区显示「已达到 3 个文件上限」并禁用。

### 4.3 当前 KB 信息卡片简化

- 内边距从当前较大的 padding 收紧到 `12px 16px`。
- 分块方式、embedding 模型、文档数、片段数使用水平小标签组展示，而不是多行文本。
- 不新增/删除字段，只调整布局。

### 4.4 文档列表项微调

- 每个文档行的操作按钮（查看/刷新/删除）统一加 `aria-label`。
- 刷新按钮在刷新过程中显示 spinner，避免用户不知道正在刷新。
- 文档名过长时使用 `text-overflow: ellipsis`，避免撑破布局。

### 4.5 管理知识库弹窗联动

- 弹窗标题保持「管理知识库」。
- 「创建知识库」按钮改为 `.btn-primary`。
- 知识库列表空状态用 `EmptyState`（`icon=book`）。
- 文档列表空状态用 `EmptyState`（`icon=file-text`）。
- 弹窗关闭后，如果当前选中的 KB 被删除，自动切换到第一个可用 KB。

## 5. 收藏夹面板改动

### 5.1 文件夹可展开/收起

- 每个文件夹头部增加左侧展开箭头图标：
  - 收起状态：`>`（chevron-right）
  - 展开状态：`v`（chevron-down）
- 点击文件夹标题或箭头切换展开/收起状态。
- 默认行为：
  - 第一个非空文件夹默认展开。
  - 其余文件夹默认收起。
- 展开状态存储在组件 local state（`Map<folderId, boolean>`），不持久化到后端；刷新页面后恢复默认规则。

### 5.2 文件夹头部信息重构

- 左侧：展开箭头 + 文件夹图标 + 文件夹名称。
- 右侧：收藏数量 + 操作按钮（重命名、删除）。
- 操作按钮默认半透明 hover 时显示，减少视觉噪音。

### 5.3 收藏项展示优化

- 展开后显示内部收藏列表，保持现有消息预览、跳转、移动、删除功能。
- 空文件夹内部显示 `EmptyState`（`icon=bookmark`，title=「暂无收藏」）。
- 收藏项标题超长时截断并显示 tooltip。

### 5.4 新建/编辑弹窗优化

- 新建文件夹弹窗输入框聚焦时自动全选默认名「新文件夹」。
- 重命名时输入框预填原名称并全选。
- 删除文件夹前确认：如果文件夹内有收藏，提示「文件夹内还有 N 条收藏，确定删除吗？」

### 5.5 空状态统一

- 整个收藏夹没有任何文件夹时，面板中央显示 `EmptyState`（`icon=bookmark`，title=「暂无收藏夹」，action=「新建收藏夹」按钮）。

---

## 6. 数据/状态变更

### 6.1 新增 state

- `KnowledgePanel`：无需新增跨组件 state。
- `BookmarkPanel`：新增本地 state `expandedFolders: Set<string>` 或 `Record<string, boolean>`。

### 6.2 不改动后端 API

- 上传、索引、删除、收藏 CRUD 全部复用现有 store action。
- 不新增接口字段。

### 6.3 不改动持久化

- 收藏夹展开状态为纯前端 local state，不写入 localStorage 或后端。

## 7. 样式变更

- `frontend/src/styles/knowledge.css`：
  - 新增 `.kb-toolbar`、`.kb-toolbar-left`、`.kb-toolbar-right`、`.kb-toolbar-center`
  - 调整 `.hardware-kb-card` padding 和内部标签组
  - 调整 `.drop-zone` 文案和禁用态
  - 删除底部冗余上传按钮相关样式
- `frontend/src/styles/bookmarks.css`（或 misc.css 中相关片段）：
  - 新增 `.bookmark-folder`、`.bookmark-folder-header`、`.bookmark-folder-chevron`、`.bookmark-folder-content`
  - 折叠态使用 `display: none`（保留组件状态，不 unmount）
- 复用 `EmptyState` 组件和 `.btn-primary`/`.btn-secondary` 类。

## 8. i18n 变更

新增 key（需要同时更新 `zh.ts` 和 `en.ts`）：

- `kbDropzoneHint`：「拖拽文件到此处上传，或点击选择文件」
- `kbDropzoneDisabled`：「已达到 3 个文件上限」
- `bookmarkDeleteFolderWithItems`：「文件夹内还有 {count} 条收藏，确定删除吗？」
- `emptyBookmarkFolders`：「暂无收藏夹」

复用已有 key：
- `noCollection` / `noSourceData` / `noDocuments` / `noCollections` 等继续用于 `EmptyState.title`。

## 9. 验收标准

- [ ] 知识库顶部工具栏在任何窗口宽度下不出现按钮/下拉器重叠。
- [ ] 知识库面板只有一个上传入口（底部拖拽区）。
- [ ] 点击拖拽区或拖拽文件均可正常触发上传。
- [ ] 收藏夹文件夹默认第一个非空文件夹展开，其余收起。
- [ ] 点击文件夹标题可展开/收起，收起时收藏内容隐藏。
- [ ] 空文件夹使用 `EmptyState` 组件显示。
- [ ] 管理知识库弹窗内空状态使用 `EmptyState` 组件。
- [ ] `npx tsc --noEmit` 通过。
- [ ] 后端路由加载无异常。

---

## 10. 范围与不变项

**本次不做**：
- 不改动 RAG 检索逻辑、分块算法、索引流程。
- 不改动后端 API 或数据库 schema。
- 不改动上传文件大小/格式限制。
- 不改动收藏的跨文件夹拖拽排序。
- 不引入第三方 UI 库（继续用现有 Tailwind-like 自定义 CSS）。

**文件边界（Trae 线程）**：
- `frontend/src/components/knowledge/*` 由 T5 前端体验线程负责。
- `frontend/src/components/bookmarks/*` 由 T5 前端体验线程负责。
- 不越界修改 Agent、沙箱、硬件工作台代码。
