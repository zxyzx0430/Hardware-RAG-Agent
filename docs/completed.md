# 项目现状

## 已实现的软件能力

- Agent 工具调用、任务进度展示、权限确认和操作记录。
- 硬件工作台代码：串口扫描与监视、固件编译与烧录、接线图及引脚检查。
- 烧录后恢复串口监视的代码路径已实现。

## 2026-10-02 日期 1–3 收口

- 人工确认续跑只接受 `allow`、`deny`、`stop`；非法决定在 API 层返回 422，执行层也会拒绝，不能被误当作授权。
- 受支持的后端启动入口只接受本机环回监听地址，拒绝通配地址和局域网地址。绕过入口直接运行 Uvicorn 或配置反向代理不在这项保护内；这不是操作系统沙箱或多人部署验收。
- 上传被接收不再等同于索引完成：没有可检索向量或入库失败时进入 `error`，界面展示原因并结束加载，允许重新选择同名文件。
- 两套 RAG 评测脚本默认走 Agent 模式；有效样本必须有成功检索、知识库来源、实际引用和成功结束事件。缺失证据的样本单列为未计分，不冒充质量分数；旧聊天路径仅通过显式 `--legacy-chat` 启用。
- 隔离浏览器已查看索引成功文档的片段预览，以及未配置 Embedding 时的“索引失败”提示。真实模型 `Text` 完成三问检索路径检查，其中两问保留完整回答证据，一问因记录截断只保留部分内容证据。完整黄金集质量评分和聊天界面的引用展示仍未验收。

实际命令、测试结果与环境限制见[测试说明](testing.md)；能力差距和后续范围见[能力基线](agent-capability-baseline.md)。日期 1–3 阶段没有开发长期记忆、Skills/MCP；后续实施见下节。本轮没有执行实体设备烧录。

## 2026-10-03 Skills、手动记忆与 MCP 最小闭环

- 手动记忆：明确保存/清空、严格类型与 4,000 字符校验；省略字段读服务器设置，显式空串不回填。普通聊天、Agent、确认续跑共用快照，低优先级注入一次，不提升执行权限。真实 Text 模型已验证合成记忆生效和清空后不再生效。
- Skills 管理：标准 `SKILL.md` 与旧格式兼容、正文编辑、启停、删除确认；公共 GitHub 目录固定 SHA 预览/选择导入，新包默认停用。真实 GitHub 预览、导入、重复冲突、启用、编辑后停用和测试包删除已检查。
- Skills 使用：自动元数据发现与按需加载，手动最多三个技能；请求绑定版本和上下文预算。仅允许说明/包内白名单文本与 KB 检索，Router 硬拒绝写入、命令、硬件和 MCP，bypass 也不例外。真实 Text 模型分别完成自动/手动合成技能加载并据正文回答，轨迹不含正文。
- MCP：本机 stdio 服务添加、发现工具、启动/停止/删除与重启；配置只在内存。普通 Agent 获取独立工具快照，每次调用都单独确认，绑定 ID、参数和确切进程连接，一次性消费；拒绝/停止不执行，旧连接不转用新进程，错误/超时不冒充成功、不自动重放。
- 集成验证：实际安全 stdio 子进程、LangChain ToolNode/Agent 图和 ASGI 续跑接口测试覆盖批次逐次确认、重复/缺失确认、拒绝/停止、参数/实例篡改、并发、断连、重启、schema 与启动总时限。真实 Text 模型检查中拒绝为零次远端调用，允许为一次，均有正常最终回答。前端设置和聊天确认字段有组件/store 测试，构建和静态检查通过；精确数量见 testing.md。

### 仍未验收 / 明确不做

- 本轮新页面没有实际浏览器点击验收：内置浏览器和 Computer Use 都因 kernel assets 初始化错误不可用；不能用组件测试替代。
- 未重新做新电脑空白安装；使用已有系统 Python 3.13.13 的临时源码/SQLite 回归，不覆盖旧 `.venv`。
- 不支持任意 Skills 脚本执行、自动安装依赖、私有 GitHub 导入、自动提取/语义长期记忆、远程 MCP/OAuth/市场，也不承诺任意第三方包完全适配。
- MCP 服务是真实本机进程，不是操作系统沙箱；停止不等于撤销已经完成的外部动作。只将可信已安装服务加入本机配置，结果会发送给当前模型。
- 完整 RAG 黄金集质量分数、引用 UI、实体烧录/自动重连仍待专门验收。没有新增这些方向的开发。

现有工作区可继续开发与人工测试，但尚不能称“全部功能完整验收”或“远端基线已更新”。执行子任务默认 GPT-6 Luna/max，不自动升级更贵模型。

## 2026-10-04 RAG P0 软件收口

- 缓存按知识库范围及本进程内容版本验证；删除、停用、配置更新、导入和入库使旧结果失效，在途旧查询不能回填为新版本缓存。
- 同步解析、入库/BM25 和导入移出事件循环；索引并发上限为每进程 2，取消等待工作线程完成才释放许可，删除与入库变更串行防止目标复活。这些保护是单进程，不保证多进程内容版本同步。
- `webfetch` 的 HTTP、重定向策略、连接、空正文和超时失败不再包装为成功；保留成功载荷、禁用自动重定向，安全错误不包含 URL 凭据或查询串。另补当前 WebFetch 请求范围内的 HTTPX URL 日志脱敏，取消/异常和重叠抓取结束后清理，不全局静音其他请求日志。
- 校准固定公开资料及黄金集中的 GPIO 模式、NVIC 分组、UART 算术和 ESP32-S3 strapping 管脚；加入确定性回归。保留修复前的原始答案和评分失败，不回填旧成绩。
- 首轮聊天及人工确认续跑区分完成、错误与等待；保留部分正文和确认快照。无正文及已知上游零输出使用独立错误码，实际无进展超时不会被自身心跳或空 chunk 无限推迟，不自动重放模型请求/工具。主动停止与异常分开。
- 评测保留失败和真实分母；单项不可用不算零分，标准总分只统计四项完整的样本。评分采用完整检索上下文及异步截止，环境不支持时在实网请求前退出；规则诊断不冒充标准分。

完整后端 549 项通过，前端 86 项及静态检查/构建通过；旧集成失败和修复证据保留。精确记录及真实 smoke 结果以[测试记录](testing.md)和[质量基线第 8 节](rag-quality-baseline.md#8-2026-10-04-p0-实施与新验收)为准。完整标准质量分数仍未测得；不是新电脑安装、浏览器或硬件验收，也没有据此启用 P1/P2 的查询改写、自动记忆或更强重排。

最终真实 Text 四问都正常完成：三道资料题实际检索/来源链路 3/3，空库无来源且明确缺资料。严格内容诊断只通过 2/3，G026 缺少 GPIO46 电压角色的明确否定说明；还发现句子引用依据及来源页字段一致性需要 P1 核对。因此软件修复可继续开发，但不宣称严格 RAG 内容或全量质量验收完成。原答案和失败均保留，未额外重试改成绩，测试服务已关闭。

- 新增 `scripts/gitnexus.ps1`，固定 GitNexus 1.6.12 并传入完整 pnpm 原生构建授权，避免生成的 `.gitnexus/run.cjs` 漏掉 Tree-sitter 语言包。
- 2026-09-23 增量更新后的本地图谱包含 430 个文件、11,916 个节点、21,267 条边和 700 条执行流；索引对应代码提交 `e12a4c3c`，同时包含当前未提交工作区内容。
- GitNexus `context`、`trace`、`impact` 可用。FTS / VECTOR 扩展仍不可用：LadybugDB 扩展服务器连接失败，本机缺少 OpenSSL 3；恢复网络与依赖后，用 `./scripts/gitnexus.ps1 analyze --repair-fts` 修复并以 `doctor` 验收。该入口只在显式修复时临时设置 `GITNEXUS_LBUG_EXTENSION_INSTALL=auto`，结束后恢复原环境变量。
