## 一、先看结论

项目已具备本地聊天、会话、知识库、Agent 工具调用、MCP 接入、权限确认和硬件工作台等主要软件路径。当前最值得投入的不是再搭一套框架，而是将已有能力打通、纠正容易误导用户的状态，并建立可复现的质量评测。

本报告用四种标记，避免把“有入口”误写成“已验收”：

| 标记 | 含义 |
| --- | --- |
| 已有路径 | 能在当前代码中追到主要调用链；不代表真实场景完全可用。 |
| 局部闭环 | 有界面、后端和部分测试，但关键场景或异常场景没有完整证据。 |
| 未打通 | 某个入口或设置存在，尚未找到它进入最终执行结果的完整路径。 |
| 待验证 | 静态检查发现风险，仍需定向测试或实测才能确认实际影响。 |

这里的 P0/P1/P2 是**建议调查和修复的先后顺序**，不是确认所有问题都已在真实环境复现。功能线报告应提供反证并及时修订本页。

## 三、能力盘点

### 1. 知识库与 RAG（01）

**已有路径。** 知识库管理、文档上传、解析与分块、Chroma 向量检索、BM25 关键词检索、RRF 融合、重排和来源事件都存在。聊天中 Agent 可调用 `search_docs`。多查询检索另有可选封装，但默认关闭，不能写成已启用的产品能力。[知识库路由](../backend/app/api/kb_routes.py)、[检索入口](../backend/src/rag/search.py)、[多查询封装](../backend/src/rag/multi_query_retriever.py)

**状态误报已修复（2026-10-02 工作区）。** [入库代码](../backend/app/api/kb_routes.py)在零向量或入库异常时记录 `error`；[知识库界面](../frontend/src/components/knowledge/KnowledgePanel.tsx)显示失败原因、结束加载并允许同名重选。临时数据库的故障测试和真实浏览器确认了缺少 Embedding 的失败状态；固定向量的临时 Chroma 测试验证了上传→入库→检索→来源事件链路，它不是模型质量评分。

**历史问题与本轮修复分开（2026-10-03～04）。** 修复前的 35 题采集、删除后缓存命中和索引接口等待证据保留。按用户确认的 P0 顺序，2026-10-04 已实施单进程缓存版本校验、索引工作线程及并发/删除保护、网页抓取失败契约、G001/G016/G023/G026 资料和黄金答案校准，以及聊天结束可靠性修复。执行交给 Luna/max，主控复核并集成；定向回归结果和最终集成进度见 [质量基线第 8 节](rag-quality-baseline.md#8-2026-10-04-p0-实施与新验收)。多进程一致性、全量语义质量和真实浏览器体验不因这些修复自动通过。

**仍待验证。** 检索异常可变成空列表，与“确实没有相关资料”混淆。引用格式正确不证明每句话的语义忠实性；父片段与来源摘录不同，评分不能只用摘录。聊天界面引用点击、向量分批写入失败后的清理仍待专项验收；实际加载重排器后的完整质量也未验收。

**评测入口已对齐（2026-10-02 工作区）。** [黄金集脚本](../backend/tests/rag_eval/run_golden_eval.py)和[策略评测脚本](../backend/tests/rag_eval/run_eval.py)默认发送 `use_agent=true`，与聊天界面的模式一致。仅有成功的 `search_docs`、知识库来源、有效引用和成功结束事件的 Agent 样本进入计分；缺失证据、模型报错和旧路径单独标记。接口模拟与报告测试不代表真实质量评分；本轮尚未产出完整黄金集的质量分数。

**下一步：P0 余项** 完成本轮最终集成与修复后真实小样本，另在匹配的隔离 Python/DeepEval 环境重跑全量标准评分；现有评分协议修复不等于已取得质量分数。**P1** 引用语义正确性、父片段可核验、维度/降级预检和部分写入故障清理；**P2** 根据可靠对照决定是否采用多查询、查询改写或更强重排。新小样本不替代 35 题全量，也不证明通用手册问答质量全面达标。

### 2. 聊天、会话与短期记忆（02，依赖 03）

**已有路径。** 消息与会话持久化、流式显示、来源保存、人工确认后的续跑、历史压缩和会话级 Agent checkpoint 都有代码路径。[聊天路由](../backend/app/api/chat_routes.py)、[自动压缩](../backend/src/agent/compact/autocompact.py)、[checkpoint](../backend/src/agent/agent_factory.py)

**局部闭环。** 自动压缩解决长上下文预算，不等于“跨会话长期记忆”；数据库里的聊天记录也不等于模型每次都会正确取用。会话续跑与切换会话已有模拟回归测试；浏览器真实网络中断后是否能正确结束生成、保留已输出内容，仍应按[测试说明](testing.md)重新复测。不能把 2026-09-26 的自动化通过当成该浏览器场景的实测通过。

**P0 软件补强（2026-10-04 工作区）。** 空输出、精确已知的上游零输出异常和模型流无有效进展有分类；失败保留部分正文，后续结束帧或续跑收尾不覆盖失败。确认等待保留请求快照和续跑 payload，主动停止与异常分开；生产者/队列取消清理有回归。首轮结束增加 `completed`，等待增加 `awaiting_confirmation`，保留旧结束帧读取兼容。导入兼容与最终全量结果另记，不把模拟通过写成浏览器断网实测。

**优先调查：P1** 刷新、切会话、人工确认与断线时的消息一致性；**P2** 压缩前后关键约束保留率、长会话成本和上下文可见性。

### 3. 长期记忆（02 负责体验，03 负责使用策略）

**已有局部能力。** 设置页存在“长期记忆”文本框，前端随聊天请求传 `long_term_memory`。界面的会话搜索读取已保存的聊天消息；Agent 的 `search_history` 则使用另一份独立 SQLite FTS5 索引，另有仅在进程运行期间存在的语义存储。[设置页](../frontend/src/components/settings/SettingsPage.tsx)、[Agent 历史检索](../backend/src/agent/session_search.py)、[语义存储](../backend/src/agent/store_adapter.py)

**手动闭环已打通（2026-10-03 工作区）。** 明确保存/清空、严格 4,000 字符、普通/Agent 注入一次、空串和确认续跑快照均有回归；真实 Text 已证明合成记忆生效和清空失效。没有自动提取、冲突合并、语义长期记忆或历史索引联通。`InMemoryStore` 随进程结束消失，checkpoint 是执行状态，不是跨会话记忆。实际浏览器保存/清空点击仍未验收。

**下一步：P1** 补浏览器体验和记忆隐私提示验收；以后有真实需求再调查自动提取、冲突处理或历史索引。**P2** 在真实用例上比较关键词与语义召回。本轮按用户要求不开发历史搜索。

### 5. Agent 决策与安全执行（03、04）

**已有路径。** Agent 通过工具规格和路由调用领域工具；高风险操作有确认与审计链，前端有确认弹窗和审计入口。[Agent 工厂](../backend/src/agent/agent_factory.py)、[工具路由](../backend/src/agent/core/toolkit/tool_router.py)、[确认弹窗](../frontend/src/components/chat/ConfirmDialog.tsx)。04 线在当前提交上重新运行权限入口、隔离 Git 快照、请求级工具实例的三组定向测试，分别为 15、7、4 项通过；这证明这些具体保护路径有回归覆盖，**不等于真实模型下的完整确认流程或操作系统沙箱已验收**。

**待验证。** “能显示任务进度”不等于复杂任务规划稳定；“有权限确认”不等于操作系统级沙箱。要用明确场景检查循环调用、失败恢复、用户拒绝后是否停止、重启后能否续跑，以及任何本地命令是否可能越过路径/权限约束。对于外部 MCP 工具尤其不能只凭风险标记判断安全。没有完成专项威胁测试前，不能宣称安全执行已全面验收。

**本轮安全收口（2026-10-02 工作区）。** HITL 的非法 `decision` 已在 API 和执行层双重拒绝；受支持的后端启动入口限制为本机环回地址。04 线 56 项定向回归通过；00 另修正全量测试中的共享工具注册表污染，并保留高风险直接工具调用拒绝确认的回归测试。没有放宽产品权限，也没有把本机监听限制宣称为系统级隔离。

**优先调查：P1** 端到端确认/拒绝/审计和关键命令边界；**P2** 基于失败轨迹决定是否恢复循环检测、强化规划和增加可观测性。

### 6. 项目文件与硬件工作台（05、06）

## 五、各功能线下一份深入报告必须回答什么

1. **01 RAG：** 用一个固定文档和固定问题重跑上传→索引→检索→引用；给出实际状态、失败信息、来源对齐情况；修正评测入口后才报告质量分数。
2. **02 聊天/记忆：** 用可重复步骤证明长期记忆文本框是否影响回答；把会话保存、自动压缩、历史搜索和跨会话记忆分开；列出断线/刷新/续跑的已测和未测场景。
3. **03 Agent：** 追踪工具选择、失败恢复、循环和 checkpoint；给出能复现的失败或证明当前策略足够的测试，不凭旧文档判断“缺少规划”。
4. **04 Skills/MCP/安全：** 分别演示工具开关、Markdown skill、MCP 真实工具及用户确认；区分应用层路径限制与真正的系统隔离，标出高风险入口。
5. **05/06：** 只在 Agent 任务实际依赖文件或硬件动作时提供专项报告；实机与模拟证据分栏，不能互相替代。

每份报告要注明所依据的提交、是否存在未提交改动、实际运行的命令和结果、未运行的测试、代码证据、用户可感知的风险、P0–P2 建议及跨线接口依赖。**调查阶段只读；修复要另起明确任务。**
