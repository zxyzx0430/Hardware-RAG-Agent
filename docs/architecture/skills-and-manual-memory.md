## 1. 目标与范围

本轮完成两个可见能力：真正能被 Agent 使用的 Skills，以及用户手动维护的跨会话记忆。Skills 支持 GitHub 公共仓库或具体目录导入，并明确报告适配程度。

- Skills：管理、导入、查看、编辑、启用/停用；自动选择或手动指定；按需加载说明和只读资料；记录实际加载证据。
- 记忆：明确保存、重新加载、跨会话使用、修改和清空；普通聊天与 Agent 路径一致。
- 不开发历史搜索、自动记忆提取、向量记忆或自动烧录。Skills 导入不执行脚本或安装依赖；任务需要时可经既有普通工具权限链处理包内脚本，不创建独立脚本执行权限。
- 初版只支持 GitHub 公共仓库。私有仓库、其他 Git 服务、远程包安装和自动依赖安装不在本轮范围。

## 2. 实施前代码事实（不是当前缺口）

`backend/app/api/skill_routes.py` 已有 Markdown 创建、列表、删除与开关，使用 `backend/data/skills/<skill_id>/skill.md`。尚无 GitHub 导入和 Agent 加载链路。

设置页的 `skills` 实际由 `/api/tools` 填充，开关控制现有工具；不能将此列表继续冒称 Markdown Skills。保留工具开关，在界面上将“工具”和“技能”分开，不删除原有能力。

手动记忆已有 `longTermMemory` 设置、数据库设置键和 `long_term_memory` 请求字段，但当前 prompt 构造未使用该字段。现有通用设置更新先改本地状态、后台异步保存，不能直接当作“服务器保存成功”的证据。

## 3. 技能包格式与兼容性

以 [Agent Skills 规范](https://agentskills.io/specification)为新导入格式：技能根目录包含 `SKILL.md`、YAML 元数据和 Markdown 正文；保留 `references/`、`assets/`、`scripts/` 等附带目录及许可证。

- 校验 `name`、`description` 的类型和约束；保留 `license`、`compatibility`、`metadata`、`allowed-tools` 等标准字段。
- YAML 使用安全解析，拒绝非映射元数据、重复关键字段及超限内容；不执行 YAML 对象构造。
- 新包使用标准 `SKILL.md`；旧 `skill.md` 和旧 ID 继续可读，标记 legacy，不批量迁移或覆盖。
- 跨 Windows/Linux 检查文件名大小写冲突、Unicode 规范化冲突和保留名称。新包不能依赖 Windows 忽略大小写才能读到参考资料。
- 支持 UTF-8/BOM 的说明文件和 UTF-8 文本参考资料；初版可加载的资料扩展名为 `.md`、`.txt`、`.json`、`.yaml`、`.yml`、`.csv`、`.toml`。
- 二进制模板和脚本可随包保存；导入和加载本身不执行脚本或安装依赖。任务需要时只能沿用既有普通工具权限链处理，不把不支持的资料静默当成已读取。
- `allowed-tools` 是上游的实验字段，不是授权书。无法映射的工具名、命令模式或其他产品专用工具明确显示缺项；不因该字段开启工具或修改权限。

兼容状态分为“基础能力支持”“部分支持”“需审核/不支持”，同时提供机器可读原因和用户可读说明。检查只证明格式与已知能力匹配，不证明任意第三方技能的所有自然语言步骤均可完成。首次启用前必须展示正文、来源和兼容提示；导入成功不等于运行成功。

## 4. GitHub 导入流程

用户粘贴公共仓库 URL 或技能目录 URL，查看候选技能与诊断，选择一个或多个技能，再确认安装。仓库多技能时不自动全部启用。

1. 后端只接受 HTTPS `github.com` 仓库/目录链接；可明确填写 branch/tag/commit 和子目录。含斜杠的 ref 不能靠拆第一个路径段盲猜，无法无歧义解析时要求补充 ref。
2. 通过 GitHub 官方只读 API 解析具体 commit SHA；预览和安装都使用同一 SHA。若来源变化则重新预览，不在确认后偷偷改用最新版。
3. 使用受控下载定位该提交的内容。若采用仓库存档，下载、重定向和解包都必须受限；不执行 `git clone` 钩子、递归子模块、安装脚本或项目代码。
4. 在项目外临时暂存目录检查文件，最终仅安装用户选中的技能目录，不把整个仓库写入 skills 根目录。
5. 保存来源仓库、提交 SHA、原始子目录、文件清单、内容摘要和导入时间。包内不能覆盖这些宿主记录。
6. **历史设计（已被当前实现覆盖）：** 新导入技能默认停用；同名冲突返回明确错误，不覆盖本机修改。当前有效包默认可用，同名冲突仍明确拒绝且不覆盖；更新仍需重新预览并显式确认，不自动同步。
7. 原子发布经过校验的技能目录；失败不留下可用的半包，也不影响已安装技能。清理只操作本次创建且已核对的临时路径。

依据：[GitHub 内容 API](https://docs.github.com/en/rest/repos/contents)。这里只需要读取远端，不需要仓库写权限；第一版不引入 GitHub token 管理。

### 导入限制

- 固定主机白名单：`api.github.com`、`github.com`、`raw.githubusercontent.com`、`codeload.github.com`。逐次验证跳转，不接受任意下载地址、内网地址或凭证 URL。
- 拒绝绝对路径、`..`、驱动器/UNC 路径、Windows 设备名、ADS、符号链接、junction/reparse 点、子模块和路径冲突；安装与运行读取都检查实际路径仍位于技能根目录。
- 实施选择 Git Trees API + 固定 SHA 的逐文件读取，不下载/解压 ZIP，因此没有解压步骤。每次操作树响应和实际累计下载上限 20 MiB、树条目上限 5,000；每个选中包最多 128 个文件、10 MiB，单文件最多 2 MiB。树被截断时失败，不将其当成完整目录。
- 网络总时限 60 秒；限流、超时、404、损坏存档和截断目录树均明确失败，不写成空仓库或安装成功。
- 上限是第一版产品策略，不是 GitHub 平台的保证；以定向测试证明代码实际执行这些限制。

## 5. Agent 最小闭环

`skills_mode` 取 `off`、`auto`、`manual`；`skill_ids` 仅供手动指定，最多 3 个。旧客户端未传新字段时为 `off`。Skills mode 只控制技能发现与加载，不过滤普通工具或已配置 MCP；界面提供技能模式入口，不宣称这是只读工具沙箱。

- `off`：不自动发现或加载既有技能；用户在当前请求中明确导入的新技能仍可按本请求快照加载。
- `auto`：只向模型提供用户已启用且可加载的技能名称、描述和诊断；模型按任务选择并调用技能加载工具。不得预先注入所有正文。
- `manual`：后端核对用户指定 ID、启用状态、兼容性和容量后加载；空列表、未知 ID、停用技能或不支持的能力明确拒绝，不擅自换成自动模式。
- `auto/manual` 本身不授予也不剥夺工具能力；普通工具与 MCP 按原有工具启用状态、权限分类、确认流程、知识库范围和路径边界执行。
- Skill 内容和实验性 `allowed-tools` 不构成授权；`bypassPermissions` 也不会跳过原有必须确认的操作、MCP 授权或路径检查。
- 无函数调用能力的模型无法完成自动技能调用；界面明确提示不支持，不静默降级并宣称已使用技能。手动记忆仍可在普通聊天使用。

每个请求建立独立技能快照，绑定 ID、内容摘要与来源版本；新导入包只追加到当前请求，不替换已有 ID 的固定哈希。HITL 续跑沿用同一快照；技能编辑、删除或停用后不允许静默换成新内容。技能快照不改变普通工具/MCP 权限。

主说明加载上限 32 KiB，单次资料读取上限 32 KiB，技能累计上下文上限 96 KiB；超限明确失败，不截断后声称完整读过。限制只约束技能额外上下文，不代替模型整体 token 预算。

## 6. 手动长期记忆

保留现有设置字段和数据库存储，明确它是用户维护的偏好/项目背景，不是聊天历史搜索或执行权限。

- 用户编辑后明确点击保存；服务器确认后显示已保存。失败保留编辑草稿与错误，不冒称成功、不覆盖最后成功值。
- 保存完成后刷新、重启和新会话能读取该值；清空保存空字符串，不能被旧本地缓存重新补回。
- `long_term_memory` 请求内容最多 4,000 字符；拒绝错误类型与超限。省略字段可读取已保存值；显式空字符串表示本轮不使用，不回填旧值。
- 普通聊天、Agent 和授权续跑以同一请求快照使用记忆，只注入一次，不随工具循环累加。
- 记忆低于宿主安全规则和本轮明确请求，不能用“以后都免确认”等文本修改权限。
- 使用前提示：记忆会随聊天发送给用户配置的模型服务，不应保存密钥或敏感凭证。不在日志、审计事件、测试报告或 Git 中记录记忆原文。
- 自动提取、Agent 自行写入、历史索引、语义召回和记忆冲突自动合并不在本轮范围。

## 7. 可见证据与错误处理

技能界面展示来源、固定版本、兼容程度、是否启用和原因；工具开关与 Skills 分开。编辑外部技能后标记本地已修改，并重新确认启用状态。

聊天轨迹记录实际技能加载及资料读取的 ID、版本摘要、阶段和结果；不记录正文、记忆原文或密钥。请求声称要用技能但加载失败时明确失败，不伪造使用事件。

来源文档、技能说明和用户记忆可能含提示注入。提示词中的优先级说明只是辅助手段，安全验收以真正没有派发越界工具、没有访问目录外文件为准。不得宣称实现操作系统级沙箱。

## 11. 后续 MCP 最小闭环

按用户授权复用现有 MCP 管理 API、stdio 客户端和 ToolSpec 适配器。Skills/记忆定向、集成、组件、真实 GitHub/模型已测；实际浏览器受运行工具初始化错误阻塞，明确保留缺口后实施 MCP，不将其改写成完整界面验收。

- 范围：用户配置一个本机 stdio MCP 服务；启动、发现工具、Agent 选择、用户确认、返回结果、审计、停止与重新启动后再次调用。
- 动作沿既有参数化进程启动方式；不执行来自技能文本或模型回复的“自动安装 MCP”命令，不自动下载 npm/Python 包。
- 外部 MCP 工具保持 HIGH 风险并沿现有逐次确认流程；即使普通内置工具选择 `bypassPermissions` 也不自动授权外部 MCP。确认仅绑定具体工具及参数，不自动批准同轮其他外部调用。Skills mode 不排除已配置 MCP；Skills 内容和 `allowed-tools` 不改变 MCP 授权。
- 将当前已连接工具作为请求独立 ToolSpec 加入普通 Agent，避免仅注册到全局后模型仍不可见。断连、调用超时、远端业务错误、错误参数均以真正的失败结果呈现，不把错误字符串包装成成功。
- 不扩展 HTTP/SSE 远程传输、OAuth、插件市场、自动发现所有服务或 MCP resources/prompts 全功能。
- 最小实测用项目提供的安全 stdio 样例服务，只有合成 echo/求和等无文件、无网络、无设备动作的工具；它是实际 MCP 子进程与协议联调，不是 Mock，也不能证明任意第三方服务兼容。
