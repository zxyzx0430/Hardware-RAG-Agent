# Git 安全速查

先看清有哪些改动，再决定是否恢复。这个仓库常有未提交文件，操作前先检查状态。

## 先检查

    git status --short --branch
    git diff --stat
    git diff -- README.md

看清差异后再继续。未跟踪的新文件不会出现在普通 `git diff` 中，需一并查看 `git status`。

## 先留副本，再撤销

如果不确定改动能否丢弃，先把重要文件复制到仓库外的备份位置，或暂存改动：

    git stash push -u -m "保留当前现场"

`stash pop` 会把暂存的改动放回工作区；若出现冲突，先停下检查，不要强行覆盖。

## 只恢复一个已跟踪文件

确认该文件的修改可以丢弃后，才运行：

    git restore README.md

把示例文件名换成实际文件路径。此操作会丢掉该文件尚未提交的修改；它不会恢复未跟踪文件。

## 撤销已经提交的改动

协作分支优先用 `git revert <提交编号>` 生成一个反向提交。先确认提交编号和工作区状态。

## 请避免

- 不要运行 `git clean`、`git reset --hard` 或强制推送；它们可能删除本地文件或改写历史。
- 不要对自己不认识的文件执行恢复或删除。
- 没有明确要求时，不提交也不推送。

提交信息按 `type(scope): 简短说明` 编写，例：`docs: 更新测试说明`。
