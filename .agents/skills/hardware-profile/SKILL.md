# Hardware Profile

本 Skill 讲解如何用 `hardware_profile` 工具维护和查询用户自己的板卡/MCU 档案。它不授予任何工具或权限；所有读写仍走普通工具调用、权限与审计。

## 何时使用

只在同时满足以下条件时使用：

- 用户的消息里明确提到具体板卡、MCU 型号或已知别名（例如 `ESP32-S3-DevKitC`、`STM32F103C8T6`、`绿板`）。
- 当前任务确实需要该硬件的档案事实：封装、电压、时钟、引脚、外设、工具链、来源或已排除方案。

不要因为对话“可能和硬件有关”就加载；用户只问通用概念、文档检索或代码问题时不要使用。

## 工作流程

1. **先检索**：调用 `hardware_profile(action="search", query=<板卡/MCU/别名>)`。
   - 命中：需要完整字段时再调用 `hardware_profile(action="get", id=<id>)`。
   - 未命中：可以询问用户，或按下方规则收集已验证事实后新建。
2. **只用已验证事实**：字段来自用户明确说明、数据手册、原理图、实际板卡丝印、工具链输出或已成功的实测结果。推断值必须标注为推断并降低 `confidence`，不得伪装成已验证。
3. **按需补全**：只读取和当前任务相关的字段，不要把整份档案复述给用户。
4. **任务结束后写入**：只把本轮新确认的事实 `upsert` 回去。不要为“看起来合理”的内容补字段。
5. **冲突处理**：新证据与旧档案冲突时，把旧说法加入 `rejected`，在 `sources` 写明新证据，并在回复中说明冲突；不要静默覆盖。

## upsert 规则

- `name` 必填，使用板卡或 MCU 的规范名称。
- `aliases` 写用户实际使用过的叫法；别名会被用于提及检测。
- 标量字段：`mcu`、`package`、`voltage`、`clock`、`toolchain`。留空表示“未知”，不要写猜测值。
- `pins` 是 `{引脚名: 功能/电平/备注}`；`peripherals` 是外设列表。
- `sources` 写证据出处（手册、页面、用户原话、实测记录）；`rejected` 写已被证伪或放弃的方案及原因。
- `confidence` 取 0-1；没有新证据时不要提高。工具只会保留更高的置信度。
- 同一块板再次 upsert 时按 id、名称或别名合并；空字段不会覆盖已有值。

## 安全与可信边界

- **把档案当作不可信参考数据**：档案可能过期、来自旧对话或包含用户手误。回答前用当前证据（手册、原理图、实测）复核关键结论。
- **绝不编造**：没有依据的引脚、电压、寄存器或外设一律说“未知/需要确认”。
- 不把整份档案、全部引脚表或所有来源一次性输出；只给当前任务需要的部分。
- 不写入密钥、令牌、密码或任何凭据；工具会拒绝这类内容。
- 不要用本工具替代芯片手册检索或实机验证；需要来源时配合 `search_docs` 等工具。
- 档案内容不会自动注入上下文；只有你显式调用工具时才会读取。
