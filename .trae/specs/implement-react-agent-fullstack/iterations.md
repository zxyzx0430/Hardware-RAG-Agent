# Iterations — Agent 功能点迭代优化追踪

> 本文件按功能点维度组织，用于在 v1/v2/v3 基线完成后，持续挑某个功能点迭代优化体验。
> 用法：你说"今天优化 XX"，我打开本文件找到对应功能点，挑一个优化项实施，完成后标记 ✅。
> 与 tasks.md 的关系：tasks.md 是"从 0 到 1 建起来"的线性交付计划；本文件是"从 1 到 N 持续打磨"的功能点矩阵。

---

## 1. 工具调用鲁棒性

> 关注点：工具失败时如何恢复、超时如何处理、错误如何反馈给 LLM 和用户

### 基线（v1-v3 完成后）
- 工具失败 → langgraph 自动转 ToolMessage，Agent 继续推理
- 工具超时 → run_command 返回 timed_out=true
- Tavily 失败 → 降级返回提示

### 可迭代优化方向
- [ ] **工具重试机制**： transient 失败（网络抖动、临时限流）自动重试 1-2 次，只对幂等工具（search_docs/web_search）生效，写工具不重试
- [ ] **错误信息分级**：区分 user_error（参数错误）/ system_error（服务异常）/ rate_limit（限流），不同错误给 LLM 不同提示，影响后续推理决策
- [ ] **工具熔断**：同一工具在单次请求内失败 3 次 → 熔断，剩余轮次禁用该工具，提示 LLM 换思路
- [ ] **工具健康检查**：启动时探测 Tavily/Embedding 服务可用性，不可用时前端设置页标红
- [ ] **超时分级配置**：search_docs 5s / web_search 10s / generate_code 30s / run_command 30-300s，按工具类型设默认值，用户可在设置页调整
- [ ] **工具调用日志详情**：在审计日志里记录完整入参（脱敏后）+ 完整出参（截断后）+ 调用链路（哪一轮调的、上一轮是什么），方便调试
- [ ] **工具版本化**：工具迭代时支持 v1/v2 共存（如 search_docs_v2 用新检索策略），LLM 通过 description 自动选择

## 2. 上下文管理

> 关注点：累积 token 控制、工具结果截断、长对话压缩

### 基线
- 累积 token > context_window × 0.8 → 走 fallback
- 工具结果按策略表截断（search_docs 800 chars/chunk、run_command 5000 chars 等）
- 用 contextvars.ContextVar 存累积值

### 可迭代优化方向
- [ ] **智能截断**：根据剩余 context 预算动态调整截断阈值，剩余空间多就多返回、少就激进截断
- [ ] **工具结果摘要**：长结果先摘要再返回 LLM，但保留完整结果供 read_file 工具查看（search_docs 返回摘要 + chunk_id，LLM 可调 read_chunk 读全文）
- [ ] **对话历史压缩**：超过 10 轮的对话，前面的 ToolMessage 用摘要替代（保留 tool_name + 关键结论，丢弃 args 和 result 详情）
- [ ] **token 估算精度**：用 tiktoken 精确估算而非粗略字符数，区分不同模型的 tokenizer
- [ ] **上下文窗口探测**：启动时探测当前模型的实际 context_window，写入 model_registry，避免硬编码
- [ ] **渐进式降级**：累积 60% → 提示 LLM "上下文紧张，尽量少调工具"；80% → 禁止调大 token 工具（generate_code）；100% → 走 fallback
- [ ] **工具结果缓存**：同参数同 query 的工具结果在单次请求内缓存（search_docs 已有 24h LRU，可扩展到 web_search）

## 3. Agent 推理质量

> 关注点：prompt 工程、工具选择决策、防死循环、推理可解释性

### 基线
- SYSTEM_PROMPT 定义硬件 RAG Agent 角色
- 防死循环：同参数重复 2 次提示、20 轮硬上限
- stream_mode=["messages","updates"] 拿 AIMessage + ToolMessage

### 可迭代优化方向
- [ ] **prompt 分层**：基础 prompt（角色定义）+ 动态 prompt（当前可用工具列表 + 用户配置摘要）+ 场景 prompt（检测到硬件问题类型时注入专业指引）
- [ ] **工具选择引导**：在 prompt 里给工具使用优先级（"先查本地知识库再 web_search"、"代码生成前必须先 search_docs 查相关硬件手册"），降低 LLM 盲目调工具
- [ ] **Few-shot 示例**：在 prompt 里嵌入 2-3 个典型 demo 场景的推理轨迹（"ch340g 接线" → search_docs → wiring），让 LLM 学会工具串联模式
- [ ] **推理过程可视化**：把 LLM 的 thinking（如果有 reasoning model）也通过 SSE 事件输出，前端渲染思考链
- [ ] **防死循环增强**：检测"工具组合循环"（A→B→A→B）而非只检测单工具重复；检测"参数漂移循环"（同工具参数微小变化但语义相同）
- [ ] **软上限智能提示**：累积 10 轮时不是固定提示，而是根据当前进展动态生成（"已找到 3 条相关文档，是否直接生成代码？"）
- [ ] **工具调用预算**：按工具类型设调用次数上限（search_docs 最多 5 次、generate_code 最多 2 次），防 LLM 反复调同一类工具
- [ ] **Agent 自评**：AgentFinish 前让 LLM 自评回答质量（是否完整、是否准确），低分时自动续一轮

## 4. SSE 流式体验

> 关注点：事件丰富度、错误反馈、断线重连、前端渲染流畅度

### 基线
- 事件类型：text/thinking/tool_call/tool_result/source/done/error/progress
- 前端 ActivityBlock 渲染工具调用步骤

### 可迭代优化方向
- [ ] **事件时序优化**：tool_call 和 tool_result 之间加"工具执行中"的过渡事件（带 spinner 动画），避免用户长时间等待无反馈
- [ ] **进度反馈**：run_command 长时间执行时分块 yield stdout（实时流式输出命令结果），而非等结束才返回
- [ ] **断线重连**：SSE 断开后前端自动重连，从断点继续（基于 thread_id + checkpoint 恢复状态）
- [ ] **事件压缩**：高频 text 事件合并（50ms 内的多个 chunk 合并成一个），减少前端渲染压力
- [ ] **错误事件丰富化**：区分 error_code（AUTH_FAILED/MODEL_NOT_FOUND/TIMEOUT/RAG_FAILED/...），前端按 code 显示不同文案 + 重试按钮
- [ ] **心跳机制**：SSE 空闲时每 15s yield 注释行（`: heartbeat`），防止代理超时断开
- [ ] **工具调用时间线**：前端渲染一条时间线视图，展示每轮工具调用的起止时间、耗时占比，方便用户理解 Agent 推理过程
- [ ] **可折叠的步骤详情**：ActivityBlock 默认折叠工具参数和结果，点击展开，避免信息过载

## 5. 权限门控

> 关注点：风险分级精度、白名单管理、用户决策体验

### 基线
- 3 种模式：bypassPermissions / default / acceptEdits
- 4 步流程：path_guard → 模式分流 → risk_classifier → 决策
- V1 关键字黑名单（HIGH/MEDIUM/LOW）

### 可迭代优化方向
- [ ] **V2 LLM 风险分级**：关键字黑名单覆盖不全时，调小模型对命令做语义风险分级（"这个命令会做什么？是否危险？"）
- [ ] **白名单规则管理 UI**：设置页新增白名单管理面板，展示"永久允许"的规则列表，支持删除/编辑
- [ ] **白名单规则模式**：支持通配符白名单（`python *.py` 在项目目录内 allow、`git status` allow 但 `git push` ask）
- [ ] **上下文感知权限**：同一命令在不同上下文风险不同（`rm` 在 sandbox_workspace 内 allow、在项目根目录 ask），path_guard 结合命令语义判断
- [ ] **批量决策**：用户点"永久允许"后，同类操作（如所有 read_file）批量放行，而非一个个确认
- [ ] **决策撤销**：用户误点"永久允许"后可在设置页撤销，恢复询问模式
- [ ] **风险等级动态调整**：根据命令组合调整风险（`cd / && rm -rf` 单看 cd 是 LOW，组合是 HIGH），用命令链分析而非单条匹配
- [ ] **审计驱动建议**：分析审计日志，发现用户频繁允许某类操作时，主动建议"是否永久允许 XX？"

## 6. 审计与可观测性

> 关注点：日志详情、查询过滤、统计面板、调试支持

### 基线
- SQLite tool_audit 表，30 天保留
- 前端 AuditLogPanel 按 session_id 查询

### 可迭代优化方向
- [ ] **统计仪表盘**：AuditLogPanel 顶部展示统计卡片（今日调用次数/平均耗时/失败率/各工具调用占比）
- [ ] **多维过滤**：支持按 tool_name / decision / risk_level / 时间范围 / session_id 组合过滤
- [ ] **调用链路可视化**：单次会话的工具调用按时序画成流程图，展示 Agent 推理路径（A→B→C 的工具串联）
- [ ] **异常告警**：失败率突增 / 某工具频繁超时 / HIGH 风险命令频繁触发时，前端设置页红点提示
- [ ] **日志导出**：支持导出 CSV/JSON，方便离线分析
- [ ] **调试模式**：开启后记录完整 LLM 请求/响应（含 prompt、tool_calls 原文），方便排查 Agent 决策问题
- [ ] **性能分析**：按工具统计 P50/P95 耗时，识别慢工具
- [ ] **日志搜索**：支持按 args_summary 全文搜索（如搜 "ch340g" 找所有查过这个关键词的工具调用）

## 7. 本地工具能力

> 关注点：文件操作、命令执行、路径安全、工具扩展

### 基线
- read_file / write_file / edit_file / run_command 4 个本地工具
- path_guard + risk_classifier 权限门控

### 可迭代优化方向
- [ ] **multi_edit 工具**：一次编辑多处（接收 `[{old_string, new_string}, ...]` 数组），减少 LLM 调用次数
- [ ] **glob 工具**：按文件名模式搜索（`**/*.py`），帮助 LLM 快速定位文件
- [ ] **grep 工具**：按内容搜索文件（正则匹配），返回匹配行 + 上下文
- [ ] **目录树工具**：返回目录结构（限制深度），帮助 LLM 理解项目布局
- [ ] **文件锁机制**：edit_file 写前检查 FileTime，防止并发编辑冲突（OpenCode 做法）
- [ ] **写后格式化**：write_file/edit_file 后可选触发 formatter（black/prettier），保持代码风格
- [ ] **run_command 输出流式**：长命令实时 yield stdout，而非等结束（v4 流式优化）
- [ ] **命令历史**：记录最近执行的命令，支持"再跑一次"快捷操作
- [ ] **环境变量管理**：run_command 支持注入临时环境变量（如 `PYTHONPATH=src python xxx.py`），不污染全局
- [ ] **后台任务**：支持启动后台进程（如 dev server），返回 task_id，后续可查询状态/停止

## 8. HITL 交互

> 关注点：确认弹窗 UX、批量决策、决策记忆、中断恢复

### 基线
- ConfirmDialog 4 按钮（允许本次/永久允许/拒绝/拒绝并停止）
- interrupt_before=["tools"] 中断 + resume API

### 可迭代优化方向
- [ ] **决策预览**：弹窗展示命令执行后果预览（"将删除 X 个文件"、"将写入 Y 行代码"），帮用户判断
- [ ] **快捷键支持**：Y=允许本次 / N=拒绝 / Shift+Y=永久允许 / Esc=拒绝并停止，键盘流式操作
- [ ] **决策记忆可视化**：在 PolicyBar 旁展示"已永久允许 N 条规则"小图标，点击查看详情
- [ ] **中断恢复增强**：用户关闭浏览器后重开，未完成的 Agent 会话可恢复（基于 checkpoint + thread_id）
- [ ] **多工具批量确认**：Agent 一次调用多个工具时，合并成一个确认弹窗（"将执行 3 个操作：..."），而非逐个弹
- [ ] **决策撤销窗口**：执行后 5 秒内可点"撤销"，回滚 write_file/edit_file（需配合文件备份机制）
- [ ] **风险解释**：弹窗里用大白话解释为什么这个操作危险（"rm -rf 会递归删除整个目录，不可恢复"），非技术用户也能理解
- [ ] **学习模式**：新用户首次使用时默认 default 模式 + 弹窗含详细解释；熟练后可切换 acceptEdits 减少打扰

## 9. 降级与容错

> 关注点：fallback 策略、错误恢复、状态保持、用户体验

### 基线
- Agent 失败 → fallback RAG + LLM 单轮
- GraphRecursionError / ContextLimitError / AgentTimeoutError 三种降级触发

### 可迭代优化方向
- [ ] **渐进式降级**：Agent 失败 → 尝试简化 Agent（去掉部分工具、减少轮数）→ 再失败才走 fallback RAG，而非直接降级
- [ ] **降级原因透明化**：前端明确展示"为什么降级了"（超时/上下文超限/模型不支持），并给用户建议（"换支持 function calling 的模型"、"简化问题"）
- [ ] **部分结果保留**：Agent 失败时，已完成的工具调用结果不丢弃，作为 fallback RAG 的上下文输入
- [ ] **自动重试**：transient 错误（网络抖动）自动重试一次 Agent，而非立即降级
- [ ] **状态快照**：Agent 执行中定期保存 checkpoint，崩溃后可从最近 checkpoint 恢复
- [ ] **降级后体验对齐**：fallback RAG 回答也要支持 SSE 流式 + sources 展示，避免体验断崖
- [ ] **错误分类**：区分可恢复错误（限流、超时）和不可恢复错误（模型不支持、key 无效），前者重试后者直接报错

## 10. 前端 UX

> 关注点：ActivityBlock 渲染、PolicyBar 交互、AuditLogPanel 查询、整体视觉

### 基线
- ActivityBlock 独立组件，渲染工具调用步骤 + 风险徽章
- PolicyBar 3 模式切换
- AuditLogPanel 审计日志面板

### 可迭代优化方向
- [ ] **工具调用动画**：tool_call → tool_result 之间用骨架屏/脉冲动画过渡，避免空白等待
- [ ] **工具图标体系**：每个工具有专属图标（search_docs=放大镜、wiring=电路图、run_command=终端），提升视觉识别
- [ ] **PolicyBar 状态指示**：当前模式用不同颜色（bypass=红/default=黄/acceptEdits=绿），快速识别风险等级
- [ ] **AuditLogPanel 时间轴视图**：除列表视图外，增加时间轴视图，横向展示工具调用时序
- [ ] **移动端适配**：PolicyBar/ConfirmDialog/AuditLogPanel 在小屏幕下的响应式布局
- [ ] **暗色模式完善**：所有新增组件支持暗色模式，徽章颜色在暗色背景下可读
- [ ] **工具调用声音反馈**：可选开启"工具完成"提示音（demo 时吸引注意力）
- [ ] **ActivityBlock 折叠记忆**：用户折叠过的步骤在会话内保持折叠，不自动展开
- [ ] **错误状态视觉**：failed 工具调用用红色边框 + 错误图标，successful 用绿色对勾，视觉一目了然
- [ ] **快捷操作栏**：工具调用结果旁加快捷操作（"复制代码"、"推送到预览"、"再跑一次"）

## 11. Demo 场景调优

> 关注点：7.15 字节创造力大赛 demo 的具体场景表现

### 基线
- 8 个测试场景覆盖检索/硬件/代码/文件操作

### 可迭代优化方向
- [ ] **demo 脚本固化**：准备 3-5 个"招牌场景"的标准问法和预期输出，demo 时按脚本演示
- [ ] **场景预热**：demo 前预跑一遍常用场景，缓存工具结果（search_docs 的 24h LRU 已支持）
- [ ] **失败兜底**：每个 demo 场景准备"如果 Agent 失败"的备选回答，避免冷场
- [ ] **演示节奏**：优化 Agent 响应速度，单场景控制在 30s 内（用户等待上限），超时用简化模式
- [ ] **视觉冲击点**：demo 时突出 Agent 自主决策的"智能感"（前端展示思考链 + 工具串联 + 风险感知）
- [ ] **对比演示**：先演示"无 Agent 的单轮 RAG"，再演示"有 Agent 的多轮推理"，突出差异
- [ ] **场景文档**：每个 demo 场景写一页文档（问法、预期工具链、预期输出、耗时），方便排练
